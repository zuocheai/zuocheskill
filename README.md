# zuocheskill

一套对话式引导 skill 合集。你在聊天框直接说「我要搭建知识库」，它就当堂把整套 AI 知识库 + 内容产线在你电脑上搭起来——不用会写代码，也不用先懂该装什么。搭完先用起来，想多自动就说一句「升到 X 配」。

## 它治的是哪些麻烦（装之前先看这个）

自己用 AI 的人，多半都栽在这几件事上：

| 你的麻烦 | 这套怎么解 |
|---|---|
| **笔记散在各处，找不着、也不敢删** | 随手丢进对应夹子，系统按内容自己归位；**待清／待归类／待确认**三个缓冲区兜着——不确认绝不动你的东西 |
| **聊天里说过的话，隔两天就找不回来了** | 每天自动收进「沟通记录」，月底能提炼成结论和概念，不是原样堆在那儿 |
| **想记点什么，得先想好放哪、怎么写** | 不用想。像发朋友圈一样说一句就行，**背景和类型二选一带一个就行（都不带系统也能兜住）** |
| **装了一堆 AI 工具，彼此打架、重复干活** | 每个角色职责写死、按时自己转；谁在做什么、归谁管，一张表说得清 |
| **每次都要写提示词，写着写着就懒得用了** | 不写。想得起来就写细点，想不起来就随口说，系统照你的理解先办出结果，你过目点头就定 |
| **东西越攒越多，却从没变成自己的东西** | 攒的东西会定期被提炼、沉淀成能复用的结论，而不是永远躺在收藏夹里 |
| **想让它干活，又怕它乱删乱动我的文件** | **默认只读**。要动手的活（整理、归档）一律先出「建议清单」，你点头才做，且做前有备份 |

**一句话**：它不是又一个要你伺候的工具，是**替你收拾摊子的那双手**——你只管说，它负责归位、记住、提醒、和定期把散的东西收拢成能用的东西。

## 装完你的电脑上长这样

八个文件夹：`00-灵感库`／`01-项目`／`02-长期关注`／`03-参考资料`／`04-归档`／`05-产出`／`06-沉淀`／`07-系统`。

**你只需要记住一件事：东西丢进 `00-灵感库`，剩下的它自己归位。**

- 三个缓冲区兜着：`待清`（快不要了，等你点头才真删）／`待归类`（套不进哪个夹的先攒这儿）／`待确认`（你自己在外头建的夹子，它先按猜的用着、记一笔等你过目）
- **不会自动删你的东西**——AI 的动作只允许「移动／复制」
- **AI 自己推的结论一律标"待确认"**——每条沉淀都带原话、出处、可信度，事实和推断分得清

> **每个格子是干什么的、装什么、谁往里放、举什么例子 → 看 `八个格子说明.md`**

设计真源：内部开发文档（不在本包内）。骨架逻辑＝三条决策：**一次搭完**（不逐步确认）、**四档开关**（低配开箱即转、要多自动说一声）、**简化版/完整版**（同一套底座、只是开关组合）。

## 目录结构（三件都已装齐、都能当场跑完）

- `zuoche/`　主入口。只做调度：任务前路由 + 任务后导航 + 一句话速用 + 「升/降到 X 配」。具体搭建交给子 skill。
- `zuoche-start/`　起步。按决策九**一次搭完整套**：建文件夹骨架 → 落六公理 → 当堂接 `zuoche-roles` 配齐角色并点亮 → 给三行速用卡。不逐步确认。
- `zuoche-roles/`　装角色 + 四档开关。**装＝全部角色说明书一次配齐；开＝低配六帮手默认即转、升档随时说**。每个角色一张随用随查卡。
- `八个格子说明.md`　**装完先看这份**——八个文件夹挨个讲：装什么、谁往里放、规矩、以及一条真实例子。
- `高阶玩法.md`　升到中配后整份交给用户的一份（高配扩业务线也用得上）。

## 两个发布版本（同一套底座，只是开关不同 · 决策十一）

- **低配（装完就跑）**＝西厂（干活：随叫随到的值班秘书）＋户部（收纳：每天收沟通记录、分拣灵感库、备份文件和配置快照）＋司礼监（总结：每天把攒的东西提炼成概念与结论，只做"沉淀"那一半）。轻快、够用、上手快。

> **一句实话（预期管理）**：这套系统装上≠从此走上人生巅峰——它转得顺不顺，**一半看模型能力、一半看你和它的磨合**。刚搭好只是起点，觉得它笨、归得不准都正常：沟通技巧是练出来的，磨合到真顶到模型天花板，再按需求把那一步换更强的模型。**逐步升级＋打磨沟通，是必经之路，不是你用错了。**
- **中配**（加一条自媒体创作产线）＝业务线01 三件套：`翰林院`（写提纲和粗稿）→`都察院`（质检）→`大理寺`（分析质检不合格原因并完善翰林院的程序）。
- **高配**（加上管理体系）＝＋`内阁`（老板在项目中的实体）＋`钦差`（某产线负责人）＋`锦衣卫`（系统内部任务）＋`密梳`（疏通清障）＋`东厂`（每日巡检把关）。**东厂随中配**（说一声就装）；**降档只停任务、不删文件**。签到领积分不在产品角色里（教程在学习网站）；**学习站部署不是出厂角色**——要做直接说，发布须他拍板。

## 设计原则（六条公理 + 五条硬规矩）

六公理：内容才是护城河 / 角色是流程不是人设 / 定时与手动各有取舍 / 先跑起来再优化 / 说人话 / 落文件才算成。外加**一件要养成的习惯**：干砸一次就往 `07-系统/踩坑库.md` 记一行，下次开工先读。
五硬规矩：① 可复制动作（要用户做的都写成能复制粘贴的文本，不把他往外赶）；② 单步给一条默认路（不甩并列选项菜单）；③ 当堂跑完不甩外链；④ 绝不说再见（事没做到可交付节点，禁止用"下次见/这个在建"收尾）；⑤ 进度文件（每步落 `07-系统/进度.md`）。
